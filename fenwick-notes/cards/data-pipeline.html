What is a data pipeline?

the plumbing behind every dashboard and model

Plain definition

A data pipeline is a repeatable path that moves data from where it’s created to where it’s used — with steps to clean, transform, check, and deliver it on a schedule or in real time.

Typical stages

  1. Ingest — pull from APIs, databases, files, sensors, logs.
  2. Validate — schema, nulls, ranges, duplicates (catch bad data early).
  3. Transform — joins, aggregates, business rules (ETL / ELT).
  4. Store — warehouse, lake, or serving DB.
  5. Serve — BI tool, app, ML feature store, report.
  6. Observe — freshness, row counts, failures, alerts.

ETL vs ELT

ETL: transform before load (classic warehouses).

ELT: load raw first, transform in the warehouse (common with cloud scale).

Neither is “always right.” Depends on volume, tools, and who owns transforms.

What good looks like

  • Idempotent runs (safe to re-run)
  • Clear ownership + docs
  • Tests on critical fields
  • Lineage: “where did this number come from?”

Interview one-liner

“A pipeline is automated data movement with quality checks — not just a script that worked once on my laptop.”
